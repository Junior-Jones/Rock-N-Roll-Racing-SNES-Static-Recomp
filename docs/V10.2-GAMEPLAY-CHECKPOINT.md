# V10.2 gameplay checkpoint

## Purpose

The snapshot system now provides a deterministic checkpoint at the race starting grid. It removes the repeated title, menu, hero, and car-purchase route from ongoing gameplay testing. Gameplay runs have no imposed duration: load the ROM, load snapshot slot 1, and continue for as long as the current investigation needs.

The prebuilt checkpoint is test data only. It belongs in `Github/Test/Saves` and must not be placed in the official source tree or release ZIP.

## Snapshot contract

The `.scsnap` file stores the complete production state required to resume:

- S-CPU registers and WRAM;
- scheduler, DMA, input serial/auto-joy, timing, and master-clock state;
- PPU registers, VRAM, OAM, CGRAM, and completed framebuffer;
- S-SMP, ARAM, timers, S-DSP, echo/filter, and audio-clock state;
- connector instruction count and completed-frame sequence.

Runtime pointers are never trusted from disk. ROM, scheduler-owner, timing-plan, and audio-sink pointers are removed before saving and rebound to the live connector after loading. The file includes an exact-build version, ROM SHA-256 identity, payload sizes, and a payload hash. Wrong-build, truncated, extended, or corrupted files fail closed.

Queued host audio is intentionally cleared on load. Core audio state resumes exactly, while the SDL output layer begins from an empty device queue so sound from before the checkpoint cannot play late.

## Determinism proof

`tests/native/v10_2_natural_route.c` creates the checkpoint on the visible starting grid, runs to route frame 4,560, reloads the checkpoint, and replays the same inputs.

- Checkpoint route frame: 3,450
- Checkpoint completed core frame: 3,451
- Replay length: 1,110 gameplay frames
- Replayed audio frames: 591,766
- Replayed audio hash: `89E21A8918D22721`
- Final framebuffer hash: `B0CE6C1E`
- Final instruction count: 56,824,643
- Result: exact match

Evidence and the generated checkpoint are under `evidence/v10_2/natural-route/checkpoint`.
